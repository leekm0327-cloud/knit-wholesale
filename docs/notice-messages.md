# 거래처 공지 메시지

저장한 팝업 공지를 카카오 브랜드 메시지 자유형으로 보낸다. 공지 저장·수정·노출 전환만으로는 메시지가 발송되지 않는다.

## 사용 순서

1. 소유자 계정으로 **매장 운영 → 팝업 공지**에서 저장한 공지의 **거래처에게 보내기**를 연다.
2. 공지에서 가져온 문구와 이미지 포함 여부를 확인한다. 메시지 문구를 수정해도 사이트 공지는 바뀌지 않는다.
3. 받을 거래처를 개별 선택하거나 전체/최근 90일 주문 기준으로 선택한다.
4. **대상·비용 확인**에서 실제 번호, 중복 제외 사유, 연결 채널, 예상 차감액을 확인한다.
5. 확인 체크 후 **최종 발송**을 누른다. 테스트도 먼저 비용을 확인하고 최종 발송해야 한다.
6. **전달 결과 확인** 또는 **이 공지 발송 이력 → 내용·결과**로 결과를 조회한다.

## 연결 조건

- 기존 알림톡 설정의 카카오 채널과 서버의 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`을 재사용한다.
- 알림톡 사용 설정이 켜져 있어야 한다. 승인 템플릿 ID는 사용하지 않는다.
- 테스트 번호는 기존 알림톡 설정의 테스트 번호를 사용한다. 브라우저에서 임의 번호로 바꿔 요청할 수 없다.
- 솔라피에서 해당 계정/채널의 브랜드 메시지 자유형 사용이 가능해야 한다. 실제 계정의 채널·단가·잔액 확인은 발송 준비 때 수행한다.
- `targeting=I`로 고정한다. 사이트 거래처 중 채널 친구에게만 전달한다. 카카오 채널 친구 전체 목록을 가져오거나 비친구에게 확장 발송하지 않는다.
- `disableSms=true`, `type=BMS_FREE`이며 문자 발신번호는 전달하지 않는다. 문자 대체 발송 비용은 발생시키지 않는다.
- 오전 8시부터 오후 8시 50분 전(한국 시간)까지 수동 발송한다. 예약/자동 발송은 없다.
- 버튼은 **주문 사이트로 이동**, 주소는 `https://wholesale.knitcoffee.co.kr/#/catalog`다. 로그인 필요 시 사이트의 기존 로그인 흐름을 따른다.

## 내용과 대상

- 이미지: 저장한 공지의 JPG/PNG만 가능하다. 5MB 이하, 가로:세로 3:4~2:1. WEBP/GIF 공지는 이미지 제외 또는 원본 교체가 필요하다.
- 이미지 포함 문구는 400자/줄바꿈 29개, 글만 보내면 1,300자/줄바꿈 99개까지 가능하다.
- 일반 거래처 계정 중 내부 매장 계정을 제외한다. 휴대전화번호가 잘못되었거나 수신거부한 거래처는 선택할 수 없다.
- 동일 번호를 여러 거래처가 공유하면 한 번만 보낸다. 그 번호를 공유하는 거래처 중 한 곳이라도 수신거부 상태면 제외한다.
- 최근 주문은 90일 이내 취소·샘플·내부 매장 주문을 제외한 주문이다.
- 한 번에 최대 500곳을 선택한다. 채널 친구 여부는 실제 전송 단계에서 카카오가 판단하므로 전달 완료 건수는 선택한 번호 수와 다를 수 있다.

## 발송과 중복 방지

- `POST /api/admin/notice-messages/prepare`: 서버에서 문구/이미지/번호/채널/단가를 고정한 확인본을 생성한다. 발송하거나 이미지를 업로드하지 않는다.
- `POST /api/admin/notice-messages/:id/send`: 확인본을 준비한 소유자가 `{confirmed:true}`로 최종 요청해야 한다. 확인본은 10분간 유효하다.
- 실제 전송 직전 공지 버전, 번호·이름·수신거부, 채널 설정, 단가, 잔액, 발송 가능 시간을 재확인한다.
- SQLite 트랜잭션과 `(notice_id, phone)` 고유 예약으로 여러 창/중복 클릭/동시 요청을 막는다. 같은 공지의 문구를 바꿔도 전달했거나 결과가 불확실한 번호에 다시 보낼 수 없다.
- 테스트 발송은 운영 대상의 예약을 만들지 않는다.
- 이미지 업로드 실패처럼 메시지 요청 전의 실패 및 확정된 수신 실패만 번호 예약을 해제한다. 새 확인본을 만들어 실패 번호를 다시 보낼 수 있다.
- 전송 요청의 타임아웃·5xx·불완전한 응답은 실패라고 단정하지 않는다. 결과 확인 필요로 남기고 재전송을 차단한다.
- 서버 중단으로 2분 넘게 처리 중인 기록도 결과 확인 필요로 표시한다. 중단된 작업을 자동 재시도하지 않는다.
- 정상 접수(2000), 전송 중(3000), 전달 완료(4000), 오류 코드를 구분한다. 접수만으로 전달 완료 표시하지 않는다.
- 솔라피 메시지 ID/그룹 ID를 받은 기록은 조회 API로 확인한다. 응답 자체를 잃어 식별자가 없는 기록은 솔라피 콘솔에서 확인해야 하며, 사이트는 임의로 실패 처리하거나 재발송을 허용하지 않는다.
- 원본 공지를 삭제하더라도 발송 확인본과 번호별 결과는 기록 테이블에 남는다. 다만 이력 화면 진입은 해당 공지에서 하므로, 발송한 공지는 삭제보다 노출 끄기를 권장한다.

## 데이터와 검증

- 새 테이블: `notice_message_batches`, `notice_message_recipients`, `notice_message_claims`. 시작 시 멱등적으로 생성한다. 운영 주문·장부·팝업 테이블의 기존 값은 변경하지 않는다.
- 모든 기능 API는 소유자 전용이다. 외부 공유 링크나 클라이언트 번들에 키를 넣지 않는다.
- `script/tests/notice-messages.test.ts`: 임시 DATA_DIR와 로컬 가짜 SOLAPI만 사용한다. 실사용 키/전화번호를 사용하거나 메시지를 보내지 않는다.
- 기본 실행: `node --import tsx script/tests/notice-messages.test.ts` (프로젝트 의존성과 실행 Node에 맞는 better-sqlite3 필요).
- 자동 검증: 소유자 권한, 중복 번호, 수신거부, 이미지·문구, 확인 없이 발송 차단, 비용/잔액, 동시 요청, 동일 확인본 재요청, 정보 변경, 시간 만료, 일부 실패, 전달 상태, 불확실 응답, 재시작 후 중복 방지.
- 실제 계정의 BMS 이용 여부와 첫 실전 전달은 소유자가 **내 번호로 먼저 확인**에서 유료 테스트 발송을 확정해 검증한다.
