# 정산 대조 및 주문·발주 연결

운영 배포 전 수정본. 운영 주문·발주 데이터는 변경하지 않았다.

## 사용 흐름

소유자 메뉴 **재무·정산 → 정산 대조**에서 정산 월과 공급처를 고르고, 클라리멘토 XLSX 원본과 PC 카카오톡 CSV를 올린다. 기간은 전월 26일~해당월 25일이다. 엑셀 원장 수량은 1kg 기준인지 확인해야 한다. 다른 양식은 임의로 해석하지 않고 오류를 표시한다.

- 사이트 발주는 서버에서 조회한다. 수량 차이를 먼저 표시하고 원문을 펼쳐 세 자료를 함께 볼 수 있다.
- 단가·금액 차이, 반복 행, 날짜 차이, 기간 밖 내역, 거래처명 빈칸, 단위 미표기는 확인 대상으로 남는다.
- 카톡의 추가/취소/수정 요청은 별도 목록에서 원문을 보고 해석한다. 사진과 삭제된 메시지는 내용을 복원하지 않는다.
- 제외·수량 조정·추가 수량 해석은 **대조 결과에만** 적용한다. 이유를 필수로 저장하고 원문으로 되돌릴 수 있다. 실제 장부 수정은 기존 주문·발주 화면에서 별도로 한다.
- 같은 월/공급처/동일 파일 재업로드는 기존 기록을 연다. 파일이 달라지면 새 기록이며 이전 판단을 자동 전파하지 않는다.
- 사이트 발주가 달라지면 내용 기반 ID가 달라져 오래된 판단을 자동 적용하지 않는다. 저장 직전에도 사이트 스냅샷을 확인한다.
- 원문 기간 밖 카톡 전체를 DB에 저장하지 않는다. 엑셀은 기간 밖 청구 근거가 필요해 해당 원장 행을 보존한다.

## 주문·발주 보완

처리 완료 시 정상 원두 수량만 자동 발주한다. 음수 반품 라인은 별도 공장 차감 확인 대상으로 알리고 정상 품목 발주를 막지 않는다. 발주일은 처리한 오늘이 아니라 주문의 유효 날짜를 쓴다.

새 자동 발주는 주문 수정/날짜 수정/처리 완료 시 갱신한다. 기존 발주는 주문 상세에서 차이를 확인하고 명시적으로 연결해야 이후 동기화된다. 발주 관리에서 별도로 수정한 내용은 자동으로 덮어쓰지 않는다. 기존 발주 단가는 보존한다. 신규 품목은 기존의 최근 매입가 → 상품 매입원가 순서를 유지한다. 단가가 없으면 잘못된 0원 발주를 만들지 않고 확인 알림을 남긴다.

출고·정산 확정 잠금을 하면 주문 변경·발주 수정/삭제·일괄 재단가에서 보호한다. 주문 취소 시에도 잠긴 발주를 보존한다. 잠금 후 실제 추가·차감은 공장과 확인해 별도로 정산한다. 동기화 전후 내역과 잠금·취소는 `purchase_link_history`에 남는다.

수동 발주 등록은 같은 공급처·날짜·거래처·품목·수량이면 기존 발주번호를 보여주고 별도 발주인지 확인한다. 이 검사는 완전한 중복 판정이 아니라 확인 장치다. 거래처 없는 기록은 자동 판단하지 않는다.

카톡 복사에는 주문번호를 발주 식별자로 포함하고 전체 수량 수정본임을 표시한다. 환불 수량은 신규 발주 수량에서 분리한다. 복사 기능은 메시지를 전송하지 않는다.

## 검증

`node --import tsx script/tests/settlement-review.test.ts`

임시 메모리 DB와 로컬 HTTP 서버로 날짜/정상+반품/기존 발주 보존/수정 충돌/확정 잠금/동일 파일 중복/소유자 권한/원문 복원/실제 장부 불변을 확인한다. `SETTLEMENT_XLSX`, `SETTLEMENT_CSV`에 사용자 원본 경로를 전달하면 9월 원본 202행, 1,601kg(기간 밖 포함), 공급가 37,755,968원도 검증한다. 실제 파일을 저장소에 포함하지 않는다.

`node --import tsx script/tests/order-invoices.test.ts`는 외부 API를 모의 응답으로 바꿔 주문·부분 반품·세금계산서 기존 동작을 확인한다.

`node --import tsx script/build.ts` 성공. 저장소 전체 타입 검사에는 변경 전과 동일한 기존 오류 35개가 있으며 이번 추가 모듈의 새 오류는 없다.

빌드 후 `node --import tsx script/preview-settlement.ts`로 127.0.0.1:8771에서 예시 미리보기를 연다. 실제 storage 모듈·백그라운드 작업·외부 발송은 실행하지 않는다. 미리보기 DB는 메모리이며 종료하면 사라진다.

## 한계

현재 비교는 거래처·원두·포장 단위 기준의 집계와 개별 날짜/원문 확인이다. 자유로운 카톡 문장의 최종 의도, 사진 속 주문, 이월 합의, 환불의 공급처 인정 여부를 자동 확정하지 않는다. 사이트의 주문일과 실제 발주일이 다른 경우에도 확인 대상으로 보여준다. 자료 간 총수량이 같다는 이유만으로 정산 완료로 처리하지 않는다.
